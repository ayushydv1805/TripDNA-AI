# TripDNA AI: Android and Windows builds

TripDNA keeps a single React/Vite frontend. Capacitor packages the same built frontend in an Android WebView; Tauri packages it as a lightweight Windows desktop app. These wrappers do not turn the project into two separate frontends.

## What the build produces

- **TripDNA-Android.apk** — debug-signed Android APK for direct installation / sideload testing.
- **TripDNA-Windows-Setup.exe** — Windows installer (NSIS).
- **TripDNA-Windows.msi** — Windows Installer package when the runner successfully creates it.

The Android APK is signed with the standard debug certificate so it can be installed for testing. It is **not a Play Store release**. Publishing to Google Play requires a controlled release keystore and a signed release bundle/APK. Keep any signing keystore and passwords in GitHub Actions secrets; never commit them.

The Windows installer is currently unsigned. Windows may show SmartScreen/unknown-publisher warnings. A public production release should be signed with a trusted code-signing certificate.

## Build via GitHub Actions

1. Merge the native packaging changes to main.
2. Open the repository's **Actions → Build Android and Windows downloads**.
3. Choose **Run workflow** to build test artifacts. Download the Android APK and Windows installers from that workflow run's **Artifacts** section. Artifacts expire after 30 days.
4. To create permanent download links, open **Releases → Draft a new release**, choose a tag such as v1.0.0 pointing at the verified main commit, and publish it. The workflow builds both platforms for that release tag and attaches the APK, EXE, and any MSI file to the release. If a build fails, fix the workflow/build first and rerun it.

Latest release page: https://github.com/ayushydv1805/TripDNA-AI/releases/latest

## Native API configuration

Packaged apps use VITE_API_BASE_URL to call the existing hosted API at https://trip-dna-ai.vercel.app. The build workflow sets this automatically. It also passes optional public frontend keys from repository Actions secrets named like VITE_GEOAPIFY_API_KEY and VITE_FIREBASE_API_KEY. If these are absent, the app can still open, but the associated provider features and Firebase cloud sign-in/backup may not work until configured.

The server functions accept the documented local/web origins and native WebView origins (https://localhost, Capacitor, and Tauri). If you move the API to another hosted domain, update VITE_API_BASE_URL and configure its allowed browser origins through the server-side TRIPDNA_ALLOWED_ORIGINS variable. Origin checks help with browser CORS but are not user authentication or a substitute for upstream API quotas/rate limiting.

AI chat and itinerary generation require OPENROUTER_API_KEY configured **server-side** on the hosted API. It must never be set as a VITE_ variable or embedded in either installer.

## Test locally

Install Node.js 24, Java 21 and Android SDK for Android builds. For desktop builds install Rust stable and the Windows C++ build tools.

~~~bash
npm install
npm run build
npx cap add android
npx cap sync android
~~~

Open the generated android/ project in Android Studio or run android/gradlew assembleDebug. For Windows, generate the icons and build the installer:

~~~bash
npx tauri icon public/favicon.svg
npm run tauri:build
~~~

Native platform directories may be generated by CI instead of being committed; this prevents large generated Android Studio files from duplicating the shared frontend source.

## Custom download URL

The permanent downloads live on GitHub Releases until a custom domain is owned and configured. A short URL such as tripdna.apk cannot be activated from repository code alone; it requires control of a domain and DNS/redirect hosting.
